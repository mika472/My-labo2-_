# AI社員採用プロジェクト 実務ガイド

**作成日**：2026年7月22日  
**プロジェクトオーナー**：株式会社Milee Growth／藤田美佳  
**使用ツール**：AI社員設計コンサルタント（Claudeプロジェクト）+ Claude.aiモバイルアプリ（音声入力）

---

## このガイドについて

このガイドは、Claudeプロジェクトで構築した「AI社員設計コンサルタント」を使い、自社に必要なAI社員を採用・導入するための実務手順書です。

7日間、1日30分のヒアリング対話を通じて、以下を設計します。

- 自社に本当に必要なAI社員の種類と人数
- 各AI社員の役割・担当業務・権限・禁止事項
- AI社員同士の組織構造と承認フロー
- 導入優先順位とロードマップ
- ClaudeでAI社員が動く仮想オフィスの生成

---

## ヒアリングの進め方

### テキスト入力の場合

Claude.ai（PC・スマートフォン）でClaudeプロジェクトを開き、テキストで回答する。

### 音声入力の場合（推奨）

1. Claude.aiモバイルアプリを開く
2. AI社員設計コンサルタントのプロジェクトを選択する
3. マイクボタンをタップして話す
4. Claudeが音声をテキスト化してヒアリングを進行する

音声入力を使うと、経営者が頭の中にある業務課題や想いを、整理しながら自然に話すことができます。テキスト入力と音声入力はどのDAYでも自由に切り替えられます。

## STEP 0：Claudeプロジェクトの準備

ヒアリングを始める前に、以下の手順でClaudeプロジェクトを設定します。

### プロジェクト作成手順

1. Claude.ai（または Claude.aiモバイルアプリ）を開く
2. 「プロジェクト」→「新しいプロジェクトを作成」を選択する
3. プロジェクト名を設定する（例：AI社員設計コンサルタント）
4. 「プロジェクト指示」に第1巻の司令塔プロンプトを貼り付ける
5. プロジェクトファイルに第1巻〜第7巻のPDF（7冊）をアップロードする

### アップロードするファイル

| ファイル | 内容 |
|---------|------|
| 第1巻：GPT System Prompt／司令塔 | Claudeの役割と進行ルール |
| 第2巻：DAY1〜DAY7 壁打ちマニュアル | ヒアリングの詳細手順 |
| 第3巻：AI社員ライブラリ | 提案できるAI社員の一覧 |
| 第4巻：ヒアリング分岐集 | 企業タイプ別の質問分岐 |
| 第5巻：成果物テンプレート | 設計書・組織図のひな型 |
| 第6巻：GPTs運用マニュアル | 運用ルールと注意事項 |
| 第7巻：AIマーケティング社員マニュアル | SNS・CTA・自動化の設計 |

### 事前に用意しておくもの

- 会社概要（業種・規模・商品サービス）
- 現在の主な経営課題（3〜5個）
- 気になっているAI社員の種類（なければ不要）
- 現在のAI活用状況

## 7日間のヒアリングフロー

### DAY 1：自社・事業・目標を整理する

**所要時間目安**：30分  
**入力方法**：テキストまたは音声

Claudeと対話しながら、以下を言語化します。

- 会社概要と事業内容
- 商品・サービスと顧客
- 現在の売上規模と今後の目標
- 現在の経営課題
- AI活用状況とAIへの理解度
- AI社員を導入したい理由・背景

**DAY1のゴール**：自社の現在地と、AI社員を必要とする背景を整理する。

**DAY1終了時にClaudeが整理するもの**
- 今日決まったこと
- まだ決まっていないこと
- 次回確認すること
- 宿題（1つ）

---

### DAY 2：業務の課題とボトルネックを洗い出す

**所要時間目安**：30分  
**入力方法**：テキストまたは音声

Claudeの質問に答えながら、以下を整理します。

- 日常業務の流れ（部門別）
- 時間がかかっている作業
- 属人化している作業
- ミスや漏れが起きやすい作業
- 従業員が負担に感じている作業
- 自動化したい業務
- AIに任せたい業務

**DAY2のゴール**：AI社員が担当できる業務候補と、事業のボトルネックを明確にする。

---

### DAY 3：必要なAI社員を診断・決定する

**所要時間目安**：30〜45分  
**入力方法**：テキストまたは音声

DAY1・DAY2の回答をもとに、Claudeが自社に必要なAI社員を提案します。

**提案に含まれる情報**：
- AI社員の種類と必要な理由
- 導入優先度
- 期待できる効果
- 導入難易度

**自分でやること**：
- 提案されたAI社員の中から、必要なものだけを選択する
- 不要なAI社員はスキップする

> 例：SNS担当が不要な場合は、マーケティング社員は設計対象外になります。AI秘書だけ必要な場合は、AI秘書だけを設計します。

**DAY3のゴール**：採用するAI社員を確定する。

---

### DAY 4：AI社員の役割と権限を設計する

**所要時間目安**：30〜45分  
**入力方法**：テキストまたは音声

選択したAI社員ごとに、以下を決めます。

| 設計項目 | 内容 |
|---------|------|
| 名前・呼称 | 社内での呼び方 |
| 所属部署・役職 | 組織上の位置づけ |
| ミッション | この社員が存在する理由 |
| 担当業務・責任範囲 | 何をやるか |
| 自動実行してよいこと | 承認なしに動ける範囲 |
| 人間の承認が必要なこと | 必ずチェックが入る業務 |
| 絶対にやってはいけないこと | 禁止事項 |
| 連携する相手 | 人間・他のAI社員との関係 |

**DAY4のゴール**：AI社員の「仕事の範囲」と「権限の境界線」を明確にする。

---

### DAY 5：AI社員の知識・性格・判断基準を設計する

**所要時間目安**：30〜45分  
**入力方法**：テキストまたは音声

各AI社員に「持たせる情報」と「振る舞い方」を設計します。

**知識設計**：
- 必要な社内知識（商品・顧客・ブランド・社内資料）
- 参照すべきドキュメント

**性格・判断基準の設計**：
- 話し方と口調
- 性格（丁寧、スピード重視、慎重 など）
- 判断の基準
- 行動ルール
- 禁止事項
- 人間にエスカレーションする条件
- 実行用プロンプト

**DAY5のゴール**：AI社員が「どのように考え、どのように動くか」を定義する。

---

### DAY 6：AI組織と承認フローを設計する

**所要時間目安**：30分  
**入力方法**：テキストまたは音声

複数のAI社員を導入する場合、組織として機能させる設計を行います。

**設計する内容**：
- AI組織図（上司・部下・同僚の関係）
- AI社員同士の業務の受け渡し方
- 人間が承認するタイミングと承認者
- 日次・週次・月次の定例業務
- KPIの確認方法
- 問題発生時の対応と最終責任者

**DAY6のゴール**：AI社員が組織として連携して動ける体制を設計する。

---

### DAY 7：全情報を統合して成果物を受け取る

**所要時間目安**：45〜60分  
**入力方法**：テキストまたは音声

DAY1〜DAY6で確定した内容をすべて統合し、以下を受け取ります。

**受け取る成果物**：
- AI社員設計書（各AI社員の完全版）
- AI組織図
- 承認フロー一覧
- 導入優先順位とロードマップ
- 運用上の注意点
- **仮想オフィス生成用プロンプト**（Claude用）

**DAY7のゴール**：AI社員採用のための完全な設計書と、仮想オフィスを生成するプロンプトを手に入れる。

---

## STEP 8：仮想オフィスを生成する

DAY7で受け取ったプロンプトを使い、仮想オフィスHTMLを生成します。

**手順**：
1. DAY7のプロンプトをコピーする
2. 同じClaudeプロジェクト（または新しいClaude会話）に貼り付ける
3. 単一のHTMLファイルが生成されることを確認する
4. HTMLをダウンロードしてブラウザで開く

**確認ポイント**：
- AI社員の名前・部署・役職が表示されているか
- 現在のタスク・ステータスが表示されているか
- ステータスカラーが正しいか
  - 🔵 青：実行中（Running）
  - 🟢 緑：完了（Done）
  - 🟠 オレンジ：承認待ち（Needs review）
- 成果物・承認待ち情報が表示されているか

**初期版の仕様**：
- 1つのHTMLファイルで完結
- CSS・JavaScriptがHTMLに埋め込まれている
- サーバー不要、インストール不要
- ブラウザで直接開ける
- 初期データは手動更新（API連携は将来対応）

---

## STEP 9：運用を開始する

仮想オフィスの確認後、実際の運用を開始します。

**運用開始チェック**：
- 各AI社員の実行プロンプトを手元に保存した
- 承認フローを関係者に共有した
- 人間が確認・承認するタイミングを周知した
- KPIの測定方法を確認した

---

## SNSマーケティング担当AI社員を導入する場合

SNS集客・認知拡大が課題の場合は、AIマーケティング社員が対応します。

### 対応SNS

- X（旧Twitter）
- Instagramカルーセル
- Instagramリール
- Threads

### KPIの管理階層

| 段階 | 主な指標 |
|------|---------|
| 認知 | インプレッション、リーチ、動画再生数、プロフィール閲覧 |
| 興味・反応 | 保存、シェア、コメント、いいね、完読率、視聴維持率 |
| 行動 | CTAクリック、LINE登録、問い合わせ、予約、資料請求 |
| 事業成果 | 商談数、成約数、売上、顧客獲得単価、投資対効果 |

**重要**：高インプレッションや成約数を保証するものではありません。仮説を立て、実行・計測・改善を繰り返して成果を積み上げます。

### コンテンツ再利用の考え方

1つのテーマを複数形式へ展開します。AIマーケティング社員は単純なコピペではなく、各SNSの閲覧文脈・文字数・テンポ・CTAに合わせて再構成します。

例：1つの長文記事 → X投稿・Xスレッド・Instagramカルーセル・Instagramリール台本・Threads投稿・メルマガ・LINE配信

## 注意事項

### 情報の扱い方

Claudeが出す情報には、以下の3種類があります。確認・意思決定の際は区別して判断してください。

- **事実・公式仕様**：確認済みの情報
- **設計提案**：ベストプラクティスに基づく提案
- **将来の拡張案**：現時点では未確定の構想

不明な情報は「未確定」として管理し、Claudeが推測で埋めることはありません。

### SNS・自動化に関するルール

- SNSの自動投稿は、各プラットフォームの最新の公式API・利用規約に従う
- 非公式なスクレイピング、大量の自動フォロー・自動DMは前提にしない
- 投稿前は必ず人間が承認する
- 個人情報、著作権、肖像権を扱う場合は確認フローを設ける
- プラットフォームの仕様変更に対応できる設計にする

### Claude Codeについて（リール編集自動化）

Claude Code自体は動画編集ソフトではありません。FFmpegなどの外部ツールを制御する「編集工程のオーケストレーター」として機能します。実際の映像処理はFFmpegや動画編集ソフトが行います。

「Claude Codeだけで何でも動画編集できる」とは断定しません。

## よくある質問

**Q. AI社員は何人必要ですか？**  
A. 企業の課題によって異なります。AI秘書だけで十分な場合もあります。人数を増やすことが目的ではなく、課題解決に必要な社員だけを採用します。

**Q. 音声入力は毎回使わないといけませんか？**  
A. どのDAYでも、テキスト入力と音声入力を自由に切り替えられます。話したほうが早い場面では音声、資料をコピーして渡したい場面ではテキストと使い分けてください。

**Q. DAYをまとめて進めてもいいですか？**  
A. 1日ずつ丁寧に進めることを推奨します。Claudeは各DAY終了後、許可なく次のDAYへ自動で進みません。

**Q. 決まらない項目があっても大丈夫ですか？**  
A. 大丈夫です。Claudeは不明な項目を「未確定」として管理し、推測で埋めません。

**Q. API連携は初めから必要ですか？**  
A. 不要です。まず手動データで仮想オフィスを動かし、運用しながら必要なAPI連携を追加していきます。

**Q. Claudeプロジェクトの会話はセッションをまたいで続きますか？**  
A. 同じプロジェクト内では会話履歴が保持されます。DAY1とDAY2を別の日に行っても、同じプロジェクトを開けばDAY1の内容を踏まえてDAY2が進みます。

## Claudeプロジェクトへの移行について（ChatGPT GPTSからの変更点）

本プロジェクトは当初、ChatGPT GPTS（カスタムGPT）での構築を想定していましたが、以下の理由からClaudeプロジェクトへ移行しました。

| 観点 | 変更内容 |
|------|---------|
| プラットフォーム | ChatGPT GPTS → Claudeプロジェクト |
| マニュアル登録先 | GPT Knowledge → Claudeプロジェクトファイル |
| 音声ヒアリング | 非対応 → Claude.aiモバイルアプリで音声入力対応 |
| 成果物生成 | 別途Claudeへ貼り付け → 同じプロジェクト内で完結 |
| セッション継続性 | セッションごとにリセット → プロジェクト内で履歴が保持 |

PDFマニュアル7冊の内容はそのまま活用できます。プロジェクト指示（Instructions）は、第1巻の司令塔プロンプトをClaudeプロジェクト向けに最適化して使用します。
