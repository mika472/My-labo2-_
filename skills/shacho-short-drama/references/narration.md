# ナレーション制作リファレンス

実案件で音声を生成し、失敗を潰した結果の知見。ここを外すと作品が台無しになる。

## 目次

1. 音声エンジンの選定（実測結果）
2. 誤読対策：熟語はすべてひらがなに開く
3. 制作順序：音声が先、映像が後
4. 一文ごとの速度設計
5. 原稿の書き方（主語・テロップ同期）

---

## 1. 音声エンジンの選定（実測結果）

**Higgsfieldのプリセット音声に日本語ネイティブは存在しない。**すべて英語話者のクローンで、
名前が日本語のものも中身は日本語話者ではない。ここを最初に共有しておかないと、
何度作り直しても「カタコト」が直らず、時間を溶かす。

実測での比較。

| エンジン | 結果 |
|---|---|
| seed_audio | カタコト。不採用 |
| text2speech_v2 / elevenlabs | 比較的自然。速度指定は不可 |
| text2speech_v2 / minimax | 遅い。ただし language_boost: "Japanese" と text_normalization: true を明示すると改善余地あり。speed 指定が効く |
| text2speech_v2 / seed_speech | elevenlabs と同程度 |
| vibe_voice / cozy_voice | プリセット音声を受け付けず生成失敗 |

speech_rate は倍率ではなく増減率のモデルがある（seed_audio は 0 が標準、-50〜100。1.3倍は 30）。
elevenlabs は speed パラメータを渡しても無視される。

**確実な解決策は2つだけ。**
1. 日本語ネイティブの音声サンプル（30秒程度）から create_voice で声を登録し、voice_type: element で使う
2. Higgsfield外の日本語TTSで生成し、音声だけ編集に持ち込む

案件の冒頭で、本人・社内・権利のある素材のいずれかで声のサンプルが用意できるか確認しておくとよい。

## 2. 誤読対策：熟語はすべてひらがなに開く

「誤読リスクのある語だけ開く」では足りない。実測での誤読例。

| 表記 | 誤読 | 正 |
|---|---|---|
| 成功者 | せいしょうしゃ | せいこうしゃ |
| 団地 | だんしょう | だんち |
| 六畳 | ろくちょう | ろくじょう |

**音読みの熟語は原則すべてひらがなに開く。**訓読みと和語は漢字のままでよい（文節認識が保たれる）。
数字も漢数字ではなくひらがなに開く（四十七歳 → よんじゅうななさい）。

開く例：成功者→せいこうしゃ／団地→だんち／六畳→ろくじょう／遺書→いしょ／八歳→はっさい／
事業→じぎょう／昭和→しょうわ／子ども部屋→こどもべや／引き出し→ひきだし／
小学二年生→しょうがくにねんせい／家→いえ／一千万円→いっせんまんえん

原稿全体をひらがなにはしない。アクセントと文節認識が崩れる。

## 3. 制作順序：音声が先、映像が後

映像を先に作ると、音声を無理な速度で押し込むことになり、必ず不自然になる。次の順で進める。

1. ショット単位でナレーションを生成する
2. 生尺を実測する
3. 一文ごとの感情設計から再生速度を決める
4. 「生尺 ÷ 速度」でそのショットの映像秒数を確定する
5. その秒数で image-to-video を生成する

実際の映像が確定秒数からズレた場合は、
**再生速度 = 音声の生尺 ÷ 映像ショットの実尺** で計算し直す。

台本を書く段階では、ElevenLabs等速で**約5.0文字／秒**、1.3倍で**約6.5文字／秒**を目安にする。
30秒の1話に入るナレーションは**170字前後が上限**。
これを超えると、間が消えるか、速度を上げてカタコトに戻るかのどちらかになる。

## 4. 一文ごとの速度設計

全体を一定速度で読ませると、AI音声だとすぐ分かる。内容に応じて変える。

| 内容 | 速度 |
|---|---|
| 話の導入 | 1.10〜1.20倍 |
| 事実・数字の提示 | 1.30〜1.40倍 |
| 反転・引きの直前 | 1.10〜1.20倍 |
| 説明・経過 | 1.35〜1.45倍 |
| 感情の頂点（開示・喪失・決断） | 0.95〜1.10倍 |
| 視聴者への語りかけ・CTA | 1.05〜1.15倍 |

平均は1.15〜1.25倍に収まる。**感情の頂点だけは絶対に速度を上げない。**
作品で一番効かせたい場所を速く流すと、そこが軽くなって全部が崩れる。

速度パラメータを持たないエンジンでは、等速で生成して編集アプリでピッチ補正つきの
タイムストレッチをかける。ショット単位で音声を分けておくと、ショットごとに速度を変えられる。

感情表現そのものは、エンジンに指示できないことが多い。
**間・句読点・改行・呼吸位置**で作る。空行が0.4〜0.7秒の間になる。
最重要の一文は前後を空行で挟むと、声量を上げずに強調できる。

## 5. 原稿の書き方

### 主語を省略しない

日本語は主語を省きがちだが、映像と切り離して聞くと誰の行為か分からなくなる。
実案件で「息子を連れて行かれた」が誰の行為か伝わらず、書き直しになった。

1. 行為の主体を必ず明示する（「息子を連れて行かれた」→「夫が息子を抱えて、家を出て行った」）
2. 受け身は、行為者が明らかな場合を除き能動態に書き換える
3. 発言はすべて話者を明示する（「銀座に、店があるんだけど」→「ある客が言った。銀座に、店があるんだけど」）
4. 心情・思考は誰のものか明示する（「生きているほうが辛かった」→「13歳の彼女は、そう思っていた」）
5. 動詞の目的語も省略しない（「彼女は決めた」→「彼女はこの家を出ると決めた」）

### テロップはナレーションと同期させる

テロップだけに新情報を足さない。実案件で、ナレーションが3000万円の話をしているのに
テロップだけ「総額2億超」と出て、辻褄が合わなくなった。

数字・固有名詞・出来事は、必ずナレーション側にも置く。
例外は年齢テロップと次回予告の2つだけ。

### ナレーションの基本

- 自然な日本語。一文を短く
- 感情的に叫ばない。静かで力のある語り
- ポエム調・説教調・広告調にしない
- 映像と感情が理解できる余白を残す
